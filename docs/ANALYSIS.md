# 요구사항 분석 및 의사결정 요청

> 산출물 1. PRD v1.0 분석, 누락/모호한 요구사항, 구현 전 확정이 필요한 질문.
> 상태: **검토 요청** · 작성일 2026-10-29

이 문서의 "제안"은 승인 전까지 가정이다. 법률·의료 판단은 확정하지 않으며 전문가 검토 대상으로 표시한다.

## 1. PRD 요약 (구현 관점)

| 영역 | MVP에서 반드시 성립해야 하는 것 |
|---|---|
| 신뢰 | 추출값은 사용자가 확정하기 전에는 비교·대시보드에 쓰이지 않는다 |
| 정확성 | 문서에 없는 수치를 만들지 않는다. 미추출은 `null`, 원문은 보존 |
| 소유권 | 모든 건강정보 리소스는 서버에서 소유자 검증 (IDOR 방지) |
| 추적성 | 원본 추출값 ↔ 확정값 ↔ 수정 이력 ↔ 출처 페이지가 연결된다 |
| 비교 안전성 | 단위·검사법이 다르면 비교를 보류하고 이유를 보여준다 |
| 비의료성 | 상승/하락을 좋음/나쁨으로 판정하지 않는다. 진단·처방 없음 |

## 2. 누락되거나 모호한 요구사항

### 2.1 상태 모델

| # | 모호점 | 제안 |
|---|---|---|
| A1 | PRD의 상태(PENDING→…→CONFIRMED)가 **작업**의 상태인지 **검진**의 상태인지 섞여 있음 | 두 개로 분리. 작업(`document_analysis_jobs.status`): `PENDING, PROCESSING, SUCCEEDED, FAILED, CANCELLED`. 검진(`checkups.status`): `DRAFT, ANALYZING, REVIEW_REQUIRED, CONFIRMED, ANALYSIS_FAILED`. 삭제는 상태가 아니라 `deleted_at`으로 처리 |
| A2 | 확정 이후 재수정 가능 여부 | 가능. 확정 후 수정 시 `measurement_revisions`에 기록하고 검진은 `CONFIRMED` 유지. 추이는 최신 확정값 사용 |
| A3 | 항목 단위 확정인지 검진 단위 확정인지 | **검진 단위 일괄 확정**(PUT measurements). 항목별 `review_status`(`PENDING/CONFIRMED/EXCLUDED`)는 내부적으로 보관 |
| A4 | 확정된 검진에 새 문서(페이지)를 추가 업로드하면? | MVP에서는 **문서 추가 = 새 검진**. 기존 검진에 문서 추가는 P1 |

### 2.2 업로드·문서

| # | 모호점 | 제안 |
|---|---|---|
| B1 | "다중 이미지"가 하나의 검진인지 | 한 번의 업로드 요청 = 하나의 검진, 이미지 여러 장 = 같은 검진의 페이지들 |
| B2 | PDF와 이미지 혼합 업로드 | MVP는 불허(PDF 1개 **또는** 이미지 1~20장) |
| B3 | 암호화된 PDF | 거부하고 "비밀번호를 해제한 파일을 올려주세요" 안내 |
| B4 | 악성 파일 검사 수단 미정 | ClamAV 컨테이너(로컬/운영). 스캔 실패 시 fail-closed(거부) |
| B5 | 중복 업로드 판단 기준 | 사용자별 파일 SHA-256 해시로 감지 → 거부하지 않고 "이미 등록된 문서" 경고 + 기존 검진 링크. 강제 진행 허용 |
| B6 | HEIC(아이폰 기본) 지원 | PRD 범위 밖. 웹에서는 브라우저가 JPEG로 변환하는 경우가 많음. MVP 제외, P1 검토 |

### 2.3 추출·측정값

| # | 모호점 | 제안 |
|---|---|---|
| C1 | 비수치 결과("음성", "1+", "정상") | `value_type`(`NUMERIC/TEXT`) 컬럼 + `raw_value` 문자열 보존. TEXT 값은 추이 그래프 대신 목록으로 표시 |
| C2 | 참고범위 형태 다양("<100", "≥60", "70-99", 성별 범위) | `reference_min`, `reference_max`, `reference_min_inclusive`, `reference_max_inclusive`, `reference_text`(원문). 파싱 불가 시 원문만 보존 |
| C3 | 혈압은 하나의 값("120/80")인가 두 항목인가 | 두 항목(`SBP`, `DBP`)으로 분리 저장. 원문은 두 항목 모두에 같은 `raw_value` 보존 |
| C4 | 단위 변환 범위 | MVP는 **변환하지 않음**. 정규화된 단위 문자열이 표준 단위와 다르면 비교 보류. 표기 차이(`mg/dl` vs `mg/dL`)만 동의어 사전으로 정규화 |
| C5 | eGFR 산식(CKD-EPI/MDRD) 차이 | `method` 컬럼(nullable). 다른 method끼리는 비교 보류 |
| C6 | 원문 판정("정상B", "질환의심") 사용 범위 | `raw_judgement`로 저장·표시만 하고 앱이 자체 판정하지 않음 |
| C7 | 출처 위치 정밀도 | `source_page` 필수 + `source_bbox`(jsonb, nullable). bbox가 있으면 원본 하이라이트 |
| C8 | BMI 자동 계산 여부 | 계산하지 않음(문서에 없는 수치 생성 금지 원칙). 문서에 있으면 추출 |

### 2.4 계정·개인정보

| # | 모호점 | 제안 |
|---|---|---|
| D1 | 이메일 인증 방식 | 6자리 코드(10분 유효, 5회 시도 제한). 링크 방식보다 모바일 앱 전환 시 재사용 쉬움 |
| D2 | 미인증 계정의 접근 범위 | 로그인은 되지만 건강정보 API는 403(`EMAIL_NOT_VERIFIED`) |
| D3 | 탈퇴 처리 | 즉시 접근 차단 + 원본 파일·건강정보 즉시 삭제, 계정 행은 익명화. 백업 파기 주기 안내(법률 검토 필요) |
| D4 | 동의 항목 | 서비스 이용약관(필수), 개인정보 수집·이용(필수), **민감정보 처리(필수, 별도 동의)**, 마케팅(선택). 버전별 이력 |
| D5 | 데이터 내보내기 | MVP: JSON + CSV(확정값만) + 원본 파일 ZIP. PDF 리포트는 P1 |
| D6 | 연령·성별 수집 여부 | MVP에서는 수집하지 않음(최소 수집). 참고범위는 문서 기재값만 사용 |

### 2.5 비기능

| # | 모호점 | 제안 |
|---|---|---|
| E1 | 분석 작업 타임아웃·재시도 횟수 | 작업당 타임아웃 3분, 자동 재시도 최대 3회(지수 백오프), 이후 FAILED + 수동 재시도 버튼 |
| E2 | 사용량 제한 | 사용자당 하루 업로드 10건(비용 상한). 초과 시 429 |
| E3 | 운영 인프라 | 미정. 로컬은 Docker Compose(PostgreSQL, MinIO, ClamAV, Mailpit). 운영은 국내 리전 클라우드 권장(국외 이전 이슈 최소화) |
| E4 | 다국어 | 한국어 단일. 문자열은 상수로 분리만 해둠 |

## 3. 구현 전 확정할 질문 (PRD §18 + 추가)

각 질문에 **제안 기본값**을 적었다. 승인하면 그대로 진행하고, 다르면 알려주면 문서를 고친다.

| # | 질문 | 제안 기본값 | 영향 범위 |
|---|---|---|---|
| Q1 | 첫 출시 플랫폼 | **모바일 반응형 Next.js 웹** | 클라이언트 전체, 인증 토큰 방식 |
| Q2 | 첫 지원 검진 양식 | **국민건강보험공단 일반건강검진 결과통보서** (가장 표준화·보급률 높음) → 이후 대형 검진센터 양식 | OCR 평가셋, 매핑 사전 |
| Q3 | OCR/문서 분석 제공업체 | 결정 보류. 어댑터 인터페이스 + **Fake 어댑터**로 개발, Sprint 3 전에 후보(국내 리전 OCR, 클라우드 Document AI, 멀티모달 LLM) 평가 | Sprint 3 일정, 위탁·국외이전 고지 |
| Q4 | 원본 파일 보관·삭제 | 사용자가 삭제할 때까지 보관. 검진 삭제 시 즉시 오브젝트 삭제, 백업은 30일 내 순환 파기(법률 검토 필요) | 스토리지·백업 정책 |
| Q5 | 이메일 인증·세션 | 6자리 코드 인증. **서버 세션 + HttpOnly Secure SameSite=Lax 쿠키**(Spring Session JDBC). 모바일 앱 추가 시 토큰 엔드포인트 확장 | 보안 구조, CSRF 대응 |
| Q6 | 출시 국가·법률 검토 | 대한민국 단독. 개인정보보호법 민감정보, 의료기기 해당성(식약처) 검토는 **출시 전 필수**로 ROADMAP에 게이트 설정 | 출시 일정 |
| Q7 | 내보내기 형식·삭제 UX | JSON/CSV/원본 ZIP. 삭제는 2단계 확인 + 무엇이 지워지는지 목록 표시 | SCR-012 |
| Q8 | 저장소 이름/구조 | 현재 디렉토리(`health-note`)를 PRD §16 구조의 루트로 사용 | 전체 |
| Q9 | 이메일 발송 서비스 | 로컬 Mailpit, 운영은 추후(SES/국내 SMTP) | Sprint 1 |
| Q10 | 프론트 착수 시점 | Sprint 1은 백엔드 기반 + 웹 스캐폴딩과 로그인 화면까지만 | Sprint 1 범위 |
